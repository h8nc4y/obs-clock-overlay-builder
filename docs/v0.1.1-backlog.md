production公開後の改善候補を、公開済みのv0.1.0とは分けて整理します。Issue #10は親backlogとして残し、個別Issueは重複しない範囲で作成します。

## v0.1.1候補

Codexだけで安全に進めやすく、OBS利用者への実利が大きい項目です。

1. PC内フォント読み込みの説明強化
   - 対象: Issue #10
   - 内容: 権限許可、空状態、OBS実行PCに同じフォントが必要なことを、非プログラマー向けに説明する。
   - 合格基準: 生成URLの `fontFamily` は実フォント名のまま、表示名だけを補助に使う。フォントファイルは同梱しない。
   - 実装状況: TB-004で完了。許可案内、空状態、表示名と実フォント名の違い、OBS実行PCで同じフォントが必要なことをUI文言と静的テストで確認する。
2. 編集画面の小さな操作性改善
   - 対象: Issue #10
   - 内容: 押しにくいボタン、説明不足、スマホ幅の横スクロール、フォーカス状態を少しずつ直す。
   - 合格基準: 390px、768px、1280px相当で横スクロールなし。Console error/warningなし。
   - 実装状況: TB-005で完了。プレビュー背景切り替えのラジオラベルを44px以上のタップ領域にし、hoverとfocus-withinでラベル全体の反応を見えるようにした。
3. manual QAとrelease手順の維持
   - 対象: Issue #10 / Issue #12
   - 内容: production後の確認手順、rollback手順、支出上限の手動確認欄を最新状態に保つ。
   - 合格基準: dashboard確認結果はIssue #12と `post-launch-ops.md` に記録する。
   - 実装状況: TB-006で完了。TB-004/TB-005のフォント・プレビュー背景確認をmanual QAへ追加し、post-launch opsにはIssue #12を起点に公開safeなdashboard確認要約だけを残す方針を明記した。
